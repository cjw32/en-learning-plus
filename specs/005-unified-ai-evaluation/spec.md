## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次运行获得可信的回归结果 (Priority: P1)

开发者从同一个入口选择 Coach、RAG、发音评测、MCP 中的一个、多个或全部模块，按案例、标签、风险和变更范围执行快速检查或完整评测。结果清楚说明实际检查了什么、如何执行、哪些没有完成，以及是否满足本次检查目的。

**Why this priority**: 消除入口分散和虚假通过，使开发者无需了解每个模块的内部脚本即可做回归检查。

**Independent Test**: 在隔离环境中分别选择四个模块及全部模块，使用已知正确与错误案例运行；再移除必需依赖、输入无效筛选条件，核对逐条记录与汇总状态。

**Acceptance Scenarios**:

1. **Given** 四模块均有已登记案例，**When** 开发者执行一次全模块快速检查，**Then** 报告展示运行前确定的案例范围、各案例模式、执行结果及门禁结论，明确其覆盖范围。
2. **Given** 开发者仅选择某个 Coach 案例或风险标签，**When** 执行评测，**Then** 展示命中案例和筛选理由；如果遗漏该验收目的的必需检查，报告只能描述局部结果，完整验收不得通过。
3. **Given** 指定了真实 Provider 模式，**When** 缺少凭证、隔离依赖或必需执行能力，**Then** 不回退为模拟通过，记录未完成的案例、原因及恢复条件。
4. **Given** 案例 ID 不存在、标签拼错、筛选后零案例或必需案例文件缺失，**When** 启动检查，**Then** 返回可判定的配置/覆盖错误及未完成状态，不产生通过结论。
5. **Given** 使用合成输入真实调用了 Provider，或对真实响应做确定性断言，**When** 查看报告，**Then** 数据来源、实际执行模式和评估器类型分别标明，不互相替代。

### User Story 2 - 比较一次 AI 变更的质量与代价 (Priority: P1)

维护者修改 Coach Prompt、RAG 切分/Embedding/检索配置、发音 Provider 或 MCP 工具后，指定基线与候选版本，在相同案例和可比较条件下查看质量、安全、延迟和成本变化，并定位受到影响的用户等级、题型或风险组。

**Why this priority**: 变更是否可接受必须依赖可追溯的比较，不能只看一次平均分或文件名中的“approved”。

**Independent Test**: 使用已冻结的案例和基线比较两个已知结果版本，注入一个局部分组回退、一个数据集版本变化及一组有波动的重复结果，核对判定。

**Acceptance Scenarios**:

1. **Given** 仅 Coach Prompt 改变，**When** 对同一验证集比较，**Then** 展示纠错、个性化、工具路径及参数的逐案差异、分组结果和双方 Prompt 身份，未改变的条件可核对。
2. **Given** 调整 RAG 切分或检索参数，**When** 比较召回及引用，**Then** 固定问题、授权语料范围和相关性判定语义；记录两侧内容/索引/Embedding 身份及相关片段映射，无法建立一致金标时标记不可直接比较。
3. **Given** 更换发音 Provider，**When** 对授权音频评测，**Then** 比较双方实际支持维度、人工一致性、逐词定位、重复波动、延迟和成本，缺失维度标为不适用或能力回归，不补造分数。
4. **Given** 总均值改善而一个必需风险组或等级组越过批准回退范围，**When** 形成结论，**Then** 该组失败不能被总均值抵消；有效样本不足或仅有小幅波动时不能宣称改进。
5. **Given** 数据集、金标、评分规则发生变化或基线未批准，**When** 请求门禁比较，**Then** 明确缺失条件，要求重跑对应基线或标记不可比较；普通运行不更新基线。

### User Story 3 - 在审查和 CI 中阻止错误的质量结论 (Priority: P1)

审查者和 CI 使用相同评测结果决定当前检查是否通过。已证实的安全和契约错误阻止通过；服务故障、未执行和主观争议分别呈现，不能用其他检查成功覆盖。

**Why this priority**: 门禁的核心价值是阻止明确回退与证据缺失被误报为验收成功。

**Independent Test**: 对同一份已知良好结果分别注入安全违规、普通阈值回退、必需检查跳过和评分争议；核对机器结果、可读报告及退出状态完全一致。

**Acceptance Scenarios**:

1. **Given** 任一案例证实跨用户泄露、未授权写入、重复写学习记录、凭证泄露或严重协议/业务契约破坏，**When** 汇总结果，**Then** 门禁失败并给出该案例证据，即使其余结果全部良好。
2. **Given** 必需真实评测因服务故障未完成且确定性检查全部通过，**When** CI 汇总，**Then** 总体验收未完成，不能显示为通过，也不能把服务故障直接当作模型回答质量下降。
3. **Given** 来自不可信外部贡献的代码变更，**When** 常规 CI 执行，**Then** 仅运行其环境允许的检查，不获得真实 Provider 或私有资源凭证；需要的真实评测仍保留为未完成，待可信环境执行。
4. **Given** 存在有效但分歧未解决的模型/人工评分，**When** 无已证实失败且必需执行已完成，**Then** 门禁待人工复核，报告保留各原始评分、理由与证据。
5. **Given** 已证实安全失败与运行异常同时存在，**When** 汇总，**Then** 主结论失败，同时保留执行未完成事实和全部原因。

### User Story 4 - 在有限预算内运行并追溯失败 (Priority: P1)

开发者在运行前设置并发、超时、重复次数和预算，在中途取消或耗尽预算后仍可读取已完成结果，并按案例、执行尝试和 Trace 找到具体失败。重跑不会抹去首次失败。

**Why this priority**: 使真实调用的开销有界，同时确保中断与重试不会制造选择性通过。

**Independent Test**: 使用受控依赖模拟慢响应、未知费用、预算耗尽、评分器崩溃及取消；检查部分结果、后续调用数量和重跑关联。

**Acceptance Scenarios**:

1. **Given** 尚有待执行案例，**When** 预算耗尽、超时或取消，**Then** 停止发起后续工作，保留已有结果及未执行清单，整轮记录为未完成；不能取消的已受理调用单独追踪终态和潜在费用。
2. **Given** 一条结果已失败，**When** 对其重跑并成功，**Then** 新结果关联首次失败，展示所有尝试和汇总规则；不得只保留成功尝试或自动将原轮改为通过。
3. **Given** Provider 不返回 Token 或实际费用，**When** 生成报告，**Then** 对应值为未知并注明原因；费用估算显示价格版本、计价单位、计算依据和覆盖范围。
4. **Given** 写操作案例使用专用测试用户，**When** 运行结束或中断，**Then** 记录测试资源、实际副作用和清理结果；无法证明隔离或存在未清理的必需资源时不能通过。

### User Story 5 - 通过项目 Skill 执行与解释评测 (Priority: P2)

贡献者向 AI 助手提出“评测这次 Coach Prompt 修改”或“解释本次门禁失败”，项目级 `run-ai-evaluation` Skill 帮助识别变更、检查前提、调用统一入口，并依据实际报告关联到 SDD 验收标准。

**Why this priority**: 把相同评测能力交给 AI 助手使用，同时保持开发者直接运行的完整能力。

**Independent Test**: 在后续实现中用 Skill 与直接入口执行同一确定性范围，比较案例、模式、版本、结果与门禁；再提供一份未完成报告，观察 Skill 是否如实解释。

**Acceptance Scenarios**:

1. **Given** 仓库内有可识别变更及有效数据集，**When** 使用 Skill 请求回归，**Then** Skill 说明变更到案例的映射、检查基线/环境/预算并调用项目入口，引用真实运行 ID、报告位置和相关验收 ID。
2. **Given** 没有执行记录、环境不可用或报告过期，**When** 要求判断是否通过，**Then** Skill 明确无法据此通过，列出缺失证据；不能虚构命令输出或将历史报告冒充本轮结果。
3. **Given** 用户仅要求运行评测，**When** 发现业务缺陷或基线不合格，**Then** Skill 输出定位与改进建议，不修改业务代码、量表、阈值、数据集或基线，不删除失败案例。
4. **Given** 不使用 Skill 的开发者，**When** 按报告中的复现方式调用相同入口，**Then** 获得相同的执行与判定能力；真实模型输出可能波动，不能承诺逐字相同。

### User Story 6 - 将经确认的线上问题加入回归集 (Priority: P2)

维护者将线上问题转化为最小化的合成重现或已授权样本，经过必要处理和人工确认后加入有版本的数据集，并与原需求、失败事实和验证用途关联。

**Why this priority**: 让评测覆盖持续改善，同时避免生产数据直接进入样本、日志或外部模型。

**Independent Test**: 提交一个合成重现、一个未授权对话片段和一个授权撤销样本，检查准入、版本变化、基线兼容提示和删除记录。

**Acceptance Scenarios**:

1. **Given** 问题可用合成数据复现且已人工确认预期行为，**When** 明确提出新增回归案例任务，**Then** 保存稳定 ID、来源、授权/使用依据、金标或量表、风险与验收关联，并发布新数据集版本。
2. **Given** 真实对话、学习记录或音频缺少授权及必要处理记录，**When** 试图加入评测集，**Then** 拒绝准入；仅删除用户名不能证明音频已匿名化。
3. **Given** 开发者已用某案例调优或检查失败详情，**When** 维护独立验证集，**Then** 记录暴露状态并管理其独立性，不能把同一问题的近重复版本当作未见验证样本。
4. **Given** 授权撤销或样本要求删除，**When** 执行数据治理，**Then** 停止使用并按适用期限删除副本及派生材料，保留不含原内容的最小审计记录，标记受影响历史结果的复现限制。

### Edge Cases

- 快速范围遗漏关键案例、过滤条件不合法、重复 ID、未知模块或无案例：不能形成虚假通过。
- 能力原本不支持、被配置关闭、运行环境缺失和候选删除已有能力必须分开：只有原规格允许的能力缺失可以判为不适用。
- 一个案例的业务执行是真实调用而评分器是模拟实现：分别标注，模拟评分不能满足必需的真实质量证据。
- 模型返回合法结构但答错、引用存在却不支持结论、评分器被候选文本指令诱导：分别按业务量表和评分器可信性处理。
- Provider 返回非法结构属于可观察输出失败；Provider 无法访问或评分器崩溃导致没有有效证据，属于未完成。对故障注入案例，正确拒绝/降级可以通过其确定性断言，但不能证明真实服务可用。
- 少量口音样本、缺失等级信息、空召回、零引用、没有音频或没有人工金标：明确有效分母、不适用/未知及证据限制，不用零值或满分填充。
- 基线与候选分组组成、缓存状态、执行模式、并发或模型实际版本不可核对：不得把差异直接归因于指定变更。
- 取消发生在外部受理或测试写入提交之后：不伪称撤销成功；保留真实状态、潜在费用及测试清理结果。
- 报告落盘/保存失败、Trace 缺失、汇总与逐案不一致：本次证据未完成；孤立的成功退出不能证明通过。
- 敏感内容出现在失败证据或录制回放中：不能以调试为由公开或长期保留；门禁仍需保存最小化违规事实。

## Requirements *(mandatory)*

### Functional Requirements

#### 统一入口、范围与执行模式

- **FR-001**: 系统 MUST 提供开发者、CI 和项目 Skill 共用的评测执行能力，支持 Coach、RAG、发音评测、MCP 单模块、多模块和全部模块；直接运行无需安装或使用 Skill。
- **FR-002**: 系统 MUST 支持案例 ID、场景标签、风险等级和变更范围筛选及组合；运行前固定并展示命中案例、选择依据、必要的跨模块影响和未覆盖项。未知条件或零命中 MUST 明确报错；影响无法确定时必须保守扩大相关范围，不能静默少测。
- **FR-003**: 系统 MUST 区分快速检查与完整评测，记录检查目的、范围、必需模式、必需案例/分组和可选检查。快速默认不产生外部费用；完整评测覆盖该目的下所有必需项。局部检查通过不得推导为未覆盖模块或发布验收通过。
- **FR-004**: 每轮 MUST 固定候选、可选的指定基线、并发上限、单案与整轮超时、重复次数、重试上限、费用/用量预算和停止条件；非法或无界配置在调用前拒绝。预算包含基线重测、候选执行、Embedding、评分模型和重试的总开销。
- **FR-005**: 系统 MUST 复用已有业务入口、案例、规则检查、指标、报告和 Trace 能力，并保留原始案例与需求映射；不能在评测系统复制业务逻辑或将“预期结果”直接用作被测业务的实际输出。历史格式缺少元数据时必须显式补充有证据的信息，不能伪造授权、版本或观测。
- **FR-006**: 每个案例及其业务、检索、语音和评分步骤 MUST 记录实际执行模式：确定性测试、Mock、录制回放、真实 Provider。确定性规则是评估器类型，合成/人工是真实数据来源属性，两者均不自动证明执行模式。依赖替身、回放来源及实际调用边界必须可见，混合运行不得只用一个笼统的 live 标签。
- **FR-007**: 真实模式 MUST 调用对应实际业务和 Provider/检索/语音能力，留下关联的观测；没有凭证、依赖、授权或可用执行能力时记为未完成，禁止静默换成 Mock。Mock/回放通过只证明已知响应下的应用或规则行为。
- **FR-008**: 系统 MUST 依据模块及 Provider/客户端实际声明和原规格约束判断能力适用性。每个不适用项必须说明能力依据并从相应指标分母排除；必需但未启用、环境缺失或候选破坏已有能力不得改为不适用以绕过门禁。

#### 数据集与四模块覆盖

- **FR-009**: 每个案例 MUST 具有稳定唯一 ID、模块、场景标签、输入和必要上下文、预期行为/参考答案/评分规则、评估器类型及版本、风险等级、来源和使用授权依据、数据集版本、关联的 SDD 需求或验收 ID。授权记录应说明用途、处理限制、撤销/删除条件；合成数据也需标明生成来源和使用依据。
- **FR-010**: 数据集 MUST 区分开发调优集和独立验证集，记录划分、近重复/同源关联及案例暴露历史；已用于调优的案例不得继续被宣称为独立验证证据。金标、内容、标签、授权或评分规则改变必须留下版本记录，不能覆盖原有事实。
- **FR-011**: 系统 MUST 复用证据盘点中的现有样本，补齐下列模块范围的关键缺口；每个必需场景至少有一个正向和一个适用的负向/边界样本。该覆盖下限只验证类别存在，不代表真实质量样本量充足；独立验证样本数、分组覆盖与最小有效量由有依据的版本化验收政策确定。
- **FR-012**: Coach MUST 覆盖纠错及解释正确性、等级匹配、练习与薄弱项匹配、工具选择/顺序/参数、结构化输出、批改和下一步建议。使用当前四类练习和成对画像检查；模型意图决策与业务代码固定的工具步骤分别报告，不把预设工具顺序视作模型自主选择成功。
- **FR-013**: RAG MUST 覆盖相关性及 Recall@K、有效引用及声明支持、忠实度、空召回、冲突、私有过滤、检索内容恶意指令，以及受变更影响的内容更新/删除/重新向量化。复用已有 Precision@K、MRR、引用覆盖等指标；记录 K、相关性金标、允许/禁止来源和每项有效分母。切分改变时金标应能对应同一语义证据，不能仅因 Chunk ID 改变误判质量。
- **FR-014**: 发音 MUST 覆盖单词、短语、单句的转写、漏读/误读/插入识别、实际支持评分维度与人工标注一致性、逐词定位、重复稳定性、噪声/静音/低置信度及合理口音差异。质量结论必须有授权音频和相应人工金标；不能仅凭转写文本、WER 或合成分数推断发音质量、公平性或人工一致性。
- **FR-015**: MCP MUST 覆盖初始化与能力发现、契约兼容、Resources/Tools/Prompts、授权和跨用户隔离、写入确认、幂等、取消及异常。工具选择质量须在指定的实际客户端与模型组合中执行并记录客户端/模型/协议/能力信息；协议模拟器通过不代表实际客户端模型选择正确。继承现有 MCP 支持范围，不能新增原始录音 Tool 或其他业务能力。

#### 评分可信性

- **FR-016**: 可确定检查的 Schema、权限、数据隔离、幂等、协议和副作用 MUST 优先依据实际行为使用规则断言；鉴权、越权和数据库写入正确性不能只靠模型评分、模型自述或测试替身声称“无违规”。
- **FR-017**: 主观质量 MUST 使用运行前固定的量表、分值锚点、判定规则和适用范围；模型评分必须记录评分 Provider/模型及可得版本、Prompt 身份及内容指纹、量表/评估器版本、分项分数、简明评分理由和可核验的候选内容/证据定位，不要求保存内部思维链或敏感系统提示全文。
- **FR-018**: 使用模型评分形成质量结论前 MUST 在独立人工标注样本上校准，记录样本及授权、评分尺度、人工复核/仲裁、模型与人工差异、批准的适用范围与校准版本。缺少校准为证据未完成；校准超出适用范围或有效评分存在分歧则待复核，不得以同一模型的自评证明质量。
- **FR-019**: 被评测输入、引用材料、工具结果和候选回答 MUST 作为不可信内容，不能改变评分指令、规则、主体或权限；评测系统必须有攻击评分器的案例。被操控、非法或非有限数值评分不可进入有效样本，保留安全诊断并标记未完成。
- **FR-020**: 有效评分分歧或证据解释不确定 MUST 标记待人工复核，展示各原始评分和分歧原因，未仲裁前不计为通过。复核决议须记录复核者、时间、依据和关联版本，并以新增记录保留原判定；批量改分、改规则必须是另一个明确任务。

#### 版本、比较与统计

- **FR-021**: 每轮 MUST 固定运行 ID/时间、代码提交及未提交改动状态和可辨识内容指纹、数据集/案例/评估器/量表版本、Prompt/工具 Schema/模型配置、Provider 与可得模型版本、RAG 内容/授权快照/切分/索引/Embedding/检索配置、发音规则及标注版本、运行环境/并发/缓存条件；不适用或不可获知字段明确注明原因，不能仅以配置别名冒充不可变模型版本。
- **FR-022**: 基线与候选 MUST 使用相同案例、金标和评分语义及可比较环境，明确本次有意改变的版本维度。Prompt、模型、Provider 或检索配置正是比较对象时，版本不同本身不构成错误；其他混杂变化必须披露并判定可比性。数据集、评分规则改变须重跑对应基线，或标为不可直接比较并禁止据此通过比较门禁。
- **FR-023**: 历史基线只有在其批准记录、版本与本轮条件匹配且未受模型漂移/数据撤权影响时才可复用；未经批准的历史运行只能作探索参考。缺少有效基线时可输出候选测量，但不能宣称满足相对基线的门禁。
- **FR-024**: 系统 MUST 同时展示整体及模块、等级、题型、风险和相关场景标签分组的结果；口音和 MCP 客户端组合另行分组。缺失属性标为未知、不适用属性注明原因；重叠标签不可重复计入总体，模型/模式不同的指标不得无说明混算。
- **FR-025**: 每项指标 MUST 给出定义/方向/单位、分子或计算基础、有效样本数、分母与排除原因。无有效样本返回未知或不适用，不能写成 0% 或 100%。Recall@K 只使用有相关性金标的适用查询，发音一致性只使用音频与人工标签齐备的样本。
- **FR-026**: 对随机性评测 MUST 支持预先指定的重复次数并展示逐次值、汇总及波动；基线与候选采用同一重复/汇总规则，保留所有尝试。重复执行同一案例不能增加独立样本数量；未满足批准的最小有效样本量和不确定性判据时，不得仅凭小幅均值变化宣称改进或达标。
- **FR-027**: 基线更新 MUST 由明确指定的独立任务驱动，固定目标运行、比较条件、批准者、时间和理由并保留历史。普通评测、CI 和 Skill 不得自动批准/覆盖基线、降低门槛、删除失败案例或反复重试挑选成功结果。

#### 质量门禁与状态

- **FR-028**: 门禁 MUST 至少区分通过、失败、未完成、待人工复核，按下表归并并列出所有原因；执行完成度与质量结论分别保留。聚合优先级为已证实失败 → 未完成 → 待人工复核 → 通过，不能用高分掩盖证据缺失。

| 结论 | 可观察条件 | 对当前声明范围的意义 |
| --- | --- | --- |
| 通过 | 必需案例/模式/分组全部完成，证据有效，适用阈值和基线条件均满足，无失败、无待复核项。 | 仅证明报告明确声明的范围满足门禁。 |
| 失败 | 已证实的阻断违规，或在充分有效证据下超出适用阈值/回退范围。 | 阻止通过；同时列出其他未完成或待复核事实。 |
| 未完成 | 缺必需案例、凭证、依赖、有效评分、批准政策/基线、可比条件或报告证据，或运行因预算/超时/取消中断，且无更高优先级失败。 | 不能完成本次验收，不能等同质量退化。 |
| 待人工复核 | 必需执行与基础证据已齐备，但有效评分、统计解释或证据判断有未决争议，且无失败或未完成条件。 | 需要可追溯人工决议，不能暂按通过处理。 |

- **FR-029**: 已证实跨用户数据泄露、未授权写入、重复写学习记录、凭证泄露、严重协议或业务契约破坏 MUST 零容忍阻断。各模块原规格中更严格的安全、引用、确认、无效写入等阻断项继续有效，不得因统一汇总被削弱。
- **FR-030**: 普通质量、延迟、成本和分组回退 MUST 使用有来源的固定阈值/容忍范围，记录来源验收 ID、适用环境、指标定义、版本及批准事实。缺少数值时保持待测量/未批准，不能从模拟报告、历史文件名或本次表现反推一个刚好通过的阈值。继承依据见“Threshold Provenance”。
- **FR-031**: 缺少关键案例、必需模式未运行、错误过滤、零案例、环境跳过及报告保存失败 MUST 阻止验收通过；可选检查未完成必须明确披露，其可选身份在运行前固定，不能在失败后改为可选。已证实的安全违规即使来自可选检查仍阻断。
- **FR-032**: 服务不可用、基础设施故障和评分器故障 MUST 与模型/业务观测失败分开记录。非法业务输出可证明契约失败；评分器非法输出不能证明候选质量失败，更不能通过。必需指标因故障无足够分母时为未完成，不能只统计成功请求而声称质量达标。

#### 有界执行、报告与失败定位

- **FR-033**: 系统 MUST 在新调用前检查剩余预算和可核算的调用上界，计入并发在途、评分器及重试支出；无法保证预算边界时拒绝新付费调用。预算耗尽、取消、超时必须停止启动后续工作，向可取消操作传递停止要求，保留部分结果和每个未完成原因。
- **FR-034**: 每次调用/重试/重复执行 MUST 关联原案例和运行，保留首次结果及全部后续尝试、次数、费用和副作用。自动重试有界并遵守原业务幂等/受理状态规则；重试成功不覆盖原始失败，新轮修复验证另行判定。
- **FR-035**: 每轮 MUST 生成机器可读结果和面向开发者的可读报告，包含运行 ID/时间/版本/模式/范围、计划与完成情况、基线和候选差异、总体/分组指标、分母、逐案结论、门禁及具体原因、复现方式。中断和前置检查失败也须尽可能产生最小诊断报告；报告无法保存时必须返回未完成并指明故障。
- **FR-036**: 报告 MUST 区分计划、通过、失败、待复核、跳过、执行异常、未执行数量及重复尝试数。完成数＝通过＋失败＋待复核；计划执行项数＝完成＋跳过＋异常＋未执行。每个执行项只归入一个终态，重复尝试单独统计；案例跨多个模式时各执行项分别计数，并另报去重案例数。筛选排除/不适用项另列，不得混入通过数量。
- **FR-037**: 每个失败/异常/待复核项 MUST 展示预期行为、实际观察、规则或量表版本、评分理由、最小必要证据、对应 Trace 或可追溯执行记录、原验收 ID 与复现条件。涉及权限和写入时须能核验实际身份边界与测试资源变化，不能仅展示最终得分。
- **FR-038**: 报告 MUST 展示适用的延迟、输入/输出 Token、Embedding/评分器用量、已知费用、估算费用和潜在未结算费用；未知不得按零计。估算附价格版本、币种、单位和计算依据，不能当作精确账单；缺少必需费用证据时成本门禁未完成。
- **FR-039**: 报告及引用的证据 MUST 绑定实际运行与内容完整性记录，汇总可从逐条结果重算；历史导入的结论不得冒充本轮执行。脱敏复现方式不得含凭证、生产标识或对生产资源的写操作。

#### CI、Skill 与数据治理

- **FR-040**: 常规 CI MUST 通过统一能力运行可稳定执行的确定性检查和快速回归；真实 Provider 检查须有明确触发条件、可信环境、案例范围和有界预算。必需检查集合按变更及验收目的在运行前固定，不能因环境不支持就自动减少发布所需证据。
- **FR-041**: CI MUST 不向不可信外部 PR 提供凭证、私有样本或测试资源访问权，也不能让其代码通过可信运行上下文间接获得凭证；环境不允许的必需真实检查保留未完成状态，等待可信执行结果。
- **FR-042**: CI MUST 保存按权限可访问的报告与失败证据，并通过机器状态及可区分退出码表达通过、失败、未完成和待复核；仅当前检查目的的通过状态可作为成功退出，不能用另一个命令成功覆盖失败/未执行检查。具体退出码、CI 平台及保存方式留到 Plan。
- **FR-043**: 本功能 MUST 定义检查行为及门禁结果；远程分支保护、必需检查绑定和部署策略属于独立配置事项。报告不能声称远程合并/发布已被技术阻止，除非另有已验证配置证据。
- **FR-044**: 后续最终交付 MUST 包含项目级 `run-ai-evaluation` Skill，限定目标仓库、触发场景、变更范围识别、跨模块影响、数据集/基线/凭证/隔离环境检查、实际命令调用、预算设置、失败和未完成处理、报告解释、案例定位、改进建议及 SDD 验收关联。
- **FR-045**: Skill MUST 从真实执行结果得出结论，引用运行 ID、报告和案例/验收 ID，并区分本轮与历史证据。默认“运行评测”仅执行检查、允许的测试资源操作/清理及生成报告；修改业务代码、数据集、评分规则、阈值或基线必须属于明确另行提出的任务，不得借评测自动修复或放宽规则。
- **FR-046**: 线上问题进入回归集 MUST 有明确新增任务、授权及必要处理记录、人工确认的预期行为和需求关联；优先合成重现。原始生产对话、学习记录和录音不得直接复用，音频不能以删用户名替代隐私处理，不得推断敏感身份属性。
- **FR-047**: 真实评测及写入检查 MUST 只在可验证的隔离测试环境使用合成/授权数据与测试用户；执行前明确允许资源、副作用和清理方式。无法验证隔离时拒绝运行；结束/中断后记录清理和残留，不能修改生产学习记录或跨测试主体共用私有缓存、上下文和引用。
- **FR-048**: 凭证 MUST 不进入案例、报告、日志或版本控制；Trace、回放和失败样本只保留定位必需内容，按最小权限限制开发者、审查者、CI 和 Skill 的访问。敏感证据只对获授权角色开放，公开报告仅含安全摘要；访问控制在自动化环境同样适用。
- **FR-049**: 每类评测产物 MUST 有运行前确定的权限、保存期限、到期删除、撤权删除及审计政策；沿用来源与模块既有更严格约束。合成/人工编写且不含个人内容的样本可按版本保留；受限内容缺少已批准期限或用途时不得收集。不得为复现无限期保留，删除须覆盖报告副本、回放、派生材料及受控分享，历史运行标明证据已删除的复现限制。

#### 评测系统自身可信性

- **FR-050**: 本功能 MUST 具备独立的已知正确/已知错误参照案例，验证正确样本通过、Schema 错误/工具选错/虚假引用失败，并通过隔离环境的实际权限与副作用观察验证越权和重复写入能触发门禁；不能只检查汇总器能接收一个手工填写的失败标记。
- **FR-051**: 系统 MUST 验证 Provider 不可用、评分器故障/非法评分、评分器注入、模式混淆、零案例/错误筛选/必需案例缺失、失败重跑、版本不兼容、分组回退、样本不足和汇总不一致均不能得到虚假通过；校准记录必须可核验。
- **FR-052**: 系统 MUST 验证并发预算、超时和取消后保留部分结果及停止后续调用，验证测试资源隔离/清理与证据删除，并对既有 Coach、RAG、发音、MCP 和学习主流程执行适用回归，证明接入评测不会带来业务行为回退或生产写入。

### Key Entities *(include if feature involves data)*

- **Evaluation Case / Dataset**: 具有稳定身份、授权、风险、输入/金标/评估规则及 SDD 关联的案例；数据集记录版本、调优/独立验证划分与暴露/删除状态。
- **Evaluation Scope**: 当前检查目的、变更依据、模块/案例/标签/风险筛选、必需和可选检查、适用能力及覆盖缺口。
- **Evaluation Run / Execution Attempt**: 固定版本与执行条件的一轮评测及逐案各模式、各次执行事实，包含预算、状态、停止原因和重试关联。
- **Version Snapshot / Baseline**: 可比较条件与观测的快照；批准基线额外包含批准身份、时间、理由、适用范围和历史记录。
- **Evaluator / Rubric / Calibration Record**: 规则或主观量表身份、版本、判定尺度，以及人工金标、模型评分差异与仲裁记录。
- **Metric / Gate Policy / Decision**: 指标定义、分母、有效样本、分组与波动；政策记录有依据的阈值和所需证据，结论记录四态及全部原因。
- **Evidence / Report / Review Record**: 逐案实际输出、Trace 关联、可读与机器报告、复现与完整性信息、人工复核；每类均受权限、期限与删除政策约束。

### Clarification Status

根据完整需求及当前四份规格，暂无必须由用户选择、否则会改变本功能范围的重大歧义。真实质量阈值、样本量、客户端/模型实际版本、预算和新产物保留政策属于以上明确的待测量/待批准依赖，不以虚构数值填补，也不要求此次提前完成 Plan 的技术选择。若后续拟缩减真实四模块验收、独立验证覆盖或原 MCP 客户端范围，必须先回到 Specify 明确澄清范围变更。

## Out of Scope

- 重写 Coach、RAG、发音评测、MCP 或复制学习业务逻辑。
- 大型评测 SaaS、完整运营后台、自动训练或微调。
- 一次评测后自动切换生产模型、自动修改 Prompt 直到当前测试集全过。
- 自动覆盖基线、删除失败案例、降低门槛或无预算多模型批量调用。
- 直接使用生产用户数据、修改生产学习记录或仅凭离线评测宣称实际学习效果提升。
- 在本阶段创建 run-ai-evaluation Skill、实现统一入口、运行付费评测、修改 CI/阈值/基线、生成实现计划或任务、提交或推送。
- 在 Specify 决定新增目录结构、依赖库、CI 平台实现、命令参数拼写、退出码数值或接口设计；这些留到 Plan。

## Assumptions

- 规格面向项目开发者、Prompt/模型/RAG/工具维护者、审查者及使用 AI 助手的贡献者；维护者承担质量政策、基线和数据使用的明确批准责任，评测执行者不能自动批准自身结果。
- 已有样本都视为开发可见的回归资产；未经独立划分和暴露审计，不宣称是未见验证集。可复用样本与不足详见 [Evidence Inventory](./evidence-inventory.md)。
- “完整”相对于预先声明的检查目的与范围；四模块完整功能验收仍需四模块必需证据，不会因只选择一个模块就缩减交付要求。
- 评测产物可继承已有更严格隐私政策；新增类别须先有明确政策再收集受限内容。合成统计元数据可用于完成本地验证，不推定真实对话或音频授权。
- 现有 Skill 的四阶段约定继续有效：Specify → Plan → Tasks → Implement。本轮停在 Specify，规格检查通过不代表实现、评测或发布已完成。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获得有依据的词汇与语法讲解 (Priority: P1)

已登录学习者向现有 Coach 询问单词释义、词性、音标、词形变化、用法、例句、搭配、语法规则、相似表达、易错点或考试题型。Coach 从当前用户可访问且来源有效的英语学习知识中检索材料，使用受控上下文生成适合其英语水平的回答，并让用户看见每项事实所依据的来源。

**Why this priority**: 可靠检索和可核验引用是本功能的核心用户价值，也是练习生成、纠错和复习建议可信的前提。

**Independent Test**: 使用具有授权来源的单词和语法样本提出事实性问题；验证检索结果与回答均符合结构合同，事实性结论只引用本次实际召回且支持该结论的来源，用户能打开对应引用内容。

**Acceptance Scenarios**:

1. **Given** 知识库中存在有效的单词释义、词性、音标和词形资料，**When** 用户询问该单词，**Then** Coach 返回与用户水平相符的讲解，并把事实性内容关联到真实来源引用。
2. **Given** 存在有效且获授权的例句或搭配资料，**When** 用户询问用法，**Then** 回答中的引用可定位到相应例句或搭配，不把模型生成示例伪装成来源例句。
3. **Given** 语法知识库中存在匹配规则，**When** 用户询问规则、例外或易错点，**Then** Coach 使用相关语法材料回答，并标出支持各事实性结论的引用。
4. **Given** 同一问题面向不同 CEFR 等级的用户，**When** Coach 构建检索请求和回答，**Then** 检索过滤、上下文选择或解释难度体现等级差异，但来源事实保持一致。

### User Story 2 - 按课程与学习状态获得个性化材料 (Priority: P1)

学习者在当前课程、学习目标、薄弱项、错题和历史学习摘要的范围内获得相关材料。公共知识、课程授权内容和当前用户私有学习内容保持清晰边界，任何个性化信号缺失时均不会被推测为事实。

**Why this priority**: 个性化检索决定 RAG 是否真正服务学习闭环，同时也是最需要保护的数据边界。

**Independent Test**: 为两个等级、课程权限、错题和学习摘要均不同的用户执行相同查询；验证过滤结果符合各自上下文，用户 A 的任何私有 Chunk、引用、Prompt、缓存或 Trace 内容都不会出现在用户 B 的请求中。

**Acceptance Scenarios**:

1. **Given** 用户有当前课程且具备该课程的访问权，**When** 用户询问课程内知识，**Then** 检索优先返回该课程的有效内容，并保留课程定位信息。
2. **Given** 用户没有目标课程的访问权，**When** 查询文本、前端过滤器或模型工具参数尝试指定该课程，**Then** 课程内容不被返回，且响应不泄露其存在性或内容摘要。
3. **Given** 用户有薄弱单词、已批改错题或最小化历史学习摘要，**When** Coach 需要个性化复习材料，**Then** 只检索当前用户的相关私有内容，并将其与公共知识明确区分。
4. **Given** 用户删除错题、历史摘要或账户，**When** 后续请求发生，**Then** 对应私有内容立即停止参与检索、上下文、引用、缓存和评测，并进入可靠删除流程。

### User Story 3 - 在依据不足时得到诚实降级 (Priority: P1)

当知识库为空、相关性低、来源无效、内容冲突无法解决或检索依赖失败时，学习者看到清晰的“依据不足”或“检索失败”状态。Coach 不编造来源，也不会因为 RAG 故障而破坏与知识库无关的基础能力。

**Why this priority**: 诚实处理未知和失败是防止虚假知识、虚假引用及错误学习记忆的核心安全门槛。

**Independent Test**: 注入空召回、全部低于门槛、相互冲突、来源已删除、检索超时和检索异常场景；验证状态分类准确，无效结果不进入最终 Prompt，回答中不存在虚假引用，现有 Coach 仍返回合法降级结果。

**Acceptance Scenarios**:

1. **Given** 没有达到最低相关性要求的结果，**When** 检索完成，**Then** 工具返回 `insufficient`，结果和引用为空或只保留明确不可用于回答的诊断信息，Coach 明确说明依据不足。
2. **Given** 高排名结果彼此冲突且无法依据来源状态、版本或权威级别消解，**When** Coach 回答，**Then** 系统标记冲突、避免把任一说法陈述为确定事实，并仅展示真实检索到的相关来源。
3. **Given** 检索服务异常或超时，**When** 用户问题仍可由非知识库基础功能处理，**Then** RAG 返回 `failed` 并触发安全降级，不阻塞现有会话、取消、重试或其他学习功能。
4. **Given** 模型输出了本次检索不存在的 `citationId`，**When** 最终结果校验，**Then** 该结果被拒绝或修复为不含虚假引用的合法降级结果。

### User Story 4 - 查看并打开来源引用卡片 (Priority: P2)

学习者在 Vue Coach 界面中看到与回答对应的引用卡片，了解来源名称、标题、分类和安全摘录，并可在权限允许时打开对应单词、课程、语法、错题或学习摘要的原始内容。

**Why this priority**: 可见、可打开的来源把后端引用约束转化为用户可验证的信任体验。

**Independent Test**: 返回包含公共词典、课程内容和本人私有错题的混合引用；验证卡片去重、关联正确、权限受控、失效状态可理解，且私有卡片不暴露不必要的原始答案或个人信息。

**Acceptance Scenarios**:

1. **Given** 回答引用同一来源的多个 Chunk，**When** 页面渲染引用，**Then** 用户看到一张去重来源卡片，并能看见该来源支持的回答部分。
2. **Given** 引用指向单词、课程或语法内容，**When** 用户点击卡片，**Then** 页面打开其有权查看的原始内容或稳定详情页定位。
3. **Given** 引用指向用户自己的错题或学习摘要，**When** 页面展示或打开卡片，**Then** 只显示完成学习任务所需的最小信息，不显示内部用户标识、其他会话原文或敏感字段。
4. **Given** 引用在回答后因原始内容删除、失效或权限变化而不可用，**When** 用户再次查看历史回答，**Then** 卡片显示“来源已失效或不可访问”，不展示缓存的受限原文。

### User Story 5 - 可靠维护知识内容生命周期 (Priority: P2)

获得授权的知识内容可以新增、更新、重新处理、失效和删除。重复摄取不会产生重复 Chunk；内容、切分规则或 Embedding 版本变化后，检索只使用当前有效版本。

**Why this priority**: 没有可靠的内容生命周期，引用会过期、重复或指向错误版本，RAG 也无法长期维护。

**Independent Test**: 对同一来源执行首次摄取、重复摄取、内容更新、切分策略变更、Embedding 版本变更、删除和恢复失败；验证 Chunk 数量、有效版本、引用状态和检索结果均符合预期。

**Acceptance Scenarios**:

1. **Given** 一份具有有效来源和授权的新内容，**When** 首次摄取完成，**Then** 其文档、Chunk、Embedding 和来源关系只在全部校验通过后成为可检索发布集合。
2. **Given** 同一内容和版本已成功摄取，**When** 摄取任务重复执行，**Then** 不新增重复文档、Chunk 或有效 Embedding。
3. **Given** 原始内容发生更新，**When** 新版本完成校验并生效，**Then** 旧 Chunk 和旧向量不再作为有效结果返回，旧引用能识别其版本已失效。
4. **Given** Embedding 模型或切分策略版本改变，**When** 系统扫描旧数据，**Then** 所有不兼容内容被识别为待重新处理，完成切换前后都不会混用无效版本。
5. **Given** 原始内容被删除或授权被撤销，**When** 删除/失效事件被接受，**Then** 内容立即从可检索集合移除，并按其数据类别完成物理删除或受控保留。

### User Story 6 - 追踪和评估 RAG 质量 (Priority: P2)

开发者和产品团队能把每次 RAG 的问题、实际过滤条件、召回结果、相关性、上下文、引用和最终回答关联到同一脱敏 Trace，并通过版本化评测集验证检索、回答、引用、安全、延迟、Token 和成本。

**Why this priority**: 没有可观测性和回归评测，就无法证明升级后的检索质量、安全性或成本可控。

**Independent Test**: 运行 RAG 专项评测集并抽查对应 Trace；验证指标定义可重复计算，检索和引用链可追踪，敏感内容已最小化，严重安全失败会阻止发布。

**Acceptance Scenarios**:

1. **Given** 一次 RAG 请求成功、依据不足或失败，**When** 授权开发者查看 Trace，**Then** 能关联问题摘要、过滤条件、版本、排名、相关性、耗时、上下文 Token、实际引用和最终反馈。
2. **Given** Prompt、Embedding 模型、切分策略、检索参数或结果 Schema 变化，**When** 候选版本进入发布评审，**Then** 完整 RAG 回归集运行并与批准基线比较。
3. **Given** 评测发现跨用户泄露、Prompt Injection 越权或虚假引用，**When** 发布门槛计算，**Then** 候选版本被阻止发布，不以平均质量分抵消严重失败。

### Edge Cases

- 查询只包含停用词、符号、超长文本、混合语言、拼写错误或 Prompt Injection 指令时，输入必须被规范化或安全拒绝，不能扩大权限范围。
- 同一原始内容产生空白、纯标题、纯链接、模板样板、重复段落或无法独立表达学习含义的片段时，这些片段不得成为有效 Chunk。
- 一个 Chunk 同时匹配多个分类、课程或单词时，元数据必须保留真实关联，过滤不能因单一标签而返回不属于请求范围的内容。
- 原始来源更新后，新版本处理失败时，旧版本可以作为明确的回滚数据保留，但不得在已确认失效、删除或撤权后继续参与检索。
- 部分 Chunk 向量化成功、部分失败时，文档版本不得被误标为完整有效；检索只使用已通过完整性门槛的发布集合。
- 相同语义结果来自多个重复来源时，结果按来源和内容去重，同时保留必要的独立来源信息用于交叉验证。
- 多个来源对同一事实表述不同但并不真正矛盾时，系统可同时返回；确有冲突时必须标记冲突，不得由模型静默选择。
- Top K 结果中只有部分通过权限、有效性或最低相关性校验时，只允许合格结果进入受控上下文，不能用低质量结果凑满数量。
- 用户没有等级、当前课程、薄弱项或历史摘要时，相应过滤器应标记为未应用，不能假设默认学习历史。
- 用户在工具参数、Prompt、URL、课程标识、单词标识或引用标识中注入另一个用户的 `userId` 时，服务端认证主体和私有过滤条件不得改变。
- 公共 Chunk 与私有 Chunk 内容相似时，去重不得使一个用户的私有版本进入另一个用户的结果、缓存或 Trace。
- 用户私有历史摘要包含第三方姓名、联系方式或完整对话时，摄取校验应拒绝或最小化这些内容，不得原样向量化。
- 知识文档内包含“忽略系统指令”“调用工具”“泄露 Prompt”等文本时，只能作为待学习的数据内容，不能改变系统规则或触发工具。
- Embedding Provider 超时、限流、返回错误维度或版本不匹配时，不得激活该向量，也不得覆盖已有有效数据。
- 检索在用户取消、JWT 过期、账户删除或权限撤销期间仍在执行时，迟到结果不得进入 Prompt、Trace 内容或前端响应。
- 历史回答引用的原始内容后来删除或撤权时，回答文本可以按既有会话生命周期保留，但引用详情必须变为失效状态且不能泄露缓存摘录。
- RAG 失败发生在普通聊天或非材料型请求中时，现有 Coach 不应被迫调用检索，也不能因 RAG 故障破坏无关流程。

### Functional Requirements

#### Scope, Sources, and Rights

- **FR-001**: 本功能 MUST 升级现有 `search_learning_materials` 工具的检索与引用能力，不得新建一套独立 Coach 或改变其受控工作流、认证主体、取消、重试、预算和最终 Schema 校验语义。
- **FR-002**: 第一阶段知识范围 MUST 能容纳已获合法使用权的单词释义、翻译、词性、音标、词形变化、例句、常见搭配、BNC/FRQ 等频率或等级字段、课程资料、语法知识、练习题型及知识点说明、当前用户错题和当前用户历史学习结构化摘要。
- **FR-003**: 每个可检索文档 MUST 关联可审计的来源记录，至少说明来源名称、原始业务记录、权利或授权状态、允许用途、内容版本、有效状态和最近核验时间。
- **FR-004**: 缺少来源、许可证、授权范围或允许用途的内容 MUST 保持不可摄取或不可发布状态；字段名为 Oxford、Collins、BNC 或 FRQ 不得被视为授权证据。
- **FR-005**: 系统 MUST NOT 擅自抓取、复制或向量化未经明确授权的第三方词典、课程、例句或互联网内容，也不得把普通联网搜索结果标记为本知识库 RAG 来源。
- **FR-006**: 例句、搭配、语法和课程正文只有在仓库或获批准的数据源中真实存在并具有来源记录时才可进入对应类别；不存在时检索 MUST 返回不可用或依据不足，不能由模型补造后回写知识库。
- **FR-007**: 用户错题 MUST 来源于当前用户已验证的练习、提交和批改事实；技术错误遥测、其他用户记录、未保存的临时模型输出和未校验草稿不得成为错题知识。
- **FR-008**: 历史学习内容 MUST 先转化为最小化、结构化、可版本化和可删除的学习摘要；完整历史对话原文不得被无差别写入知识库。
- **FR-009**: 公共知识、课程授权内容和用户私有知识 MUST 具有可测试的访问边界；课程内容不得因进入共享知识库而绕过现有购买或授权规则。
- **FR-010**: 第一阶段 MUST NOT 扩展为无边界互联网抓取、完整知识管理后台、复杂人工审核、多 Agent、English Learning MCP Server、发音评测或独立大规模向量数据库。

#### Knowledge Documents, Chunks, and Lifecycle

- **FR-011**: 知识库 MUST 在现有 PostgreSQL 数据平台内提供 pgvector 向量能力，不单独引入新的向量数据库服务。
- **FR-012**: 系统 MUST 表达 Knowledge Document、Chunk、Embedding、Source 与原始业务数据之间的关系，并能从任一检索结果追溯到当前有效来源版本。
- **FR-013**: 每个 Chunk MUST 至少具有以下元数据；可增加访问策略、文档、Chunk、状态和策略版本字段，但不得删除这些字段：

```text
source: string
sourceId: string
title: string
category: string
level: string | null
courseId: string | null
wordId: string | null
userId: string | null
visibility: "public" | "private"
contentVersion: string
embeddingVersion: string
createdAt: string
updatedAt: string
```

- **FR-014**: `sourceId` MUST 指向真实且稳定的来源业务对象；`contentVersion` MUST 随可检索语义内容变化；`embeddingVersion` MUST 能区分 Embedding 模型、向量维度和任何影响兼容性的向量生成规则。
- **FR-015**: 公共 Chunk 的 `userId` MUST 为 null；私有 Chunk 的 `userId` MUST 来自其原始业务记录的服务端所有者，并且不得接受前端、Prompt、模型或摄取载荷任意指定所有者。
- **FR-016**: 单词内容 MUST 按独立可理解的词义或用法单元切分，并保留单词、词性、音标、词形、频率/等级和授权例句/搭配的真实关联；不得把互不相关的词条合并为一个 Chunk。
- **FR-017**: 课程内容 MUST 按课程内真实章节、课时或知识点边界切分，保留课程及原始顺序定位，不得跨越权限不同或版本不同的课程内容拼接。
- **FR-018**: 语法内容 MUST 按规则、适用范围、例外、示例和易错点的语义单元切分；支持理解同一规则所必需的内容应保持可关联，不能制造脱离条件的绝对结论。
- **FR-019**: 练习与错题内容 MUST 按题目和受控知识点切分；用户私有错题只保留题目、本人答案、已验证纠正、错误类型和学习所需解释的最小集合，不得嵌入隐藏评分密钥、无关会话或其他用户信息。
- **FR-020**: 历史学习摘要 MUST 按用户、主题和明确时间/版本边界切分；摘要不得声称未被已保存学习事实支持的薄弱项或进度。
- **FR-021**: 摄取校验 MUST 拒绝空白、纯标题、纯链接、模板样板、重复、过短而没有完整学习语义、超出批准长度、结构无效或来源无效的内容。
- **FR-022**: 摄取 MUST 幂等；相同来源、内容版本、切分策略和 Chunk 内容的重复执行不得产生第二个有效文档、Chunk 或 Embedding。
- **FR-023**: 原始内容更新时，系统 MUST 创建可追踪的新内容版本，并在新版本生效时使旧 Chunk、旧向量和旧引用停止作为有效结果返回；更新失败不得造成新旧版本混杂为同一有效发布集合。
- **FR-024**: 原始内容删除、失效、授权撤销或用户删除时，对应 Chunk MUST 立即退出可检索集合；相关向量、摘录、缓存和引用详情随后按已批准生命周期删除或失效。
- **FR-025**: Embedding 模型、向量维度、切分策略或规范化规则变化时，系统 MUST 通过版本识别所有不兼容内容并重新处理；检索只能使用当前批准且兼容的发布版本。
- **FR-026**: 部分摄取、部分向量化、校验失败或版本切换中断时，文档 MUST 保持明确的非完整状态，不能对外宣称该版本可用。

#### Retrieval and Context Construction

- **FR-027**: `search_learning_materials` MUST 支持自然语言语义检索，并可按 CEFR 等级、课程、单词、知识分类、内容来源和访问范围组合过滤。
- **FR-028**: 工具请求 MUST 支持受限且可校验的 Top K 与最低相关性要求；Top K 必须有服务端硬上限，最低相关性必须来自批准配置或受限输入，模型不得关闭权限、有效性或安全过滤。
- **FR-029**: 服务端 MUST 强制把当前认证主体可访问的公共、课程授权和本人私有范围加入查询；任何客户端或模型提供的过滤器只能进一步缩小范围，不能扩大范围。
- **FR-030**: 用户等级缺失时，系统 MUST 明确记录未应用等级过滤；不得静默假定 CEFR 等级。课程或单词过滤无效、越权或与当前业务上下文冲突时必须安全拒绝或返回空结果。
- **FR-031**: 检索 MUST 在相关性门槛之后处理重复结果；相同 Chunk、相同内容版本或同一来源的等价片段不得重复占用 Top K 和上下文预算。
- **FR-032**: 检索 MUST 识别被删除、失效、过期、版本不兼容、Embedding 不兼容或来源授权无效的结果，并在进入模型上下文前排除。
- **FR-033**: 检索 MUST 对相互冲突的结果返回结构化冲突信号和相关来源；无法安全消解时不得把冲突内容作为单一确定事实传给模型。
- **FR-034**: 排名和过滤之后没有合格结果时，工具 MUST 返回 `insufficient`；依赖异常、超时或合同失败时 MUST 返回 `failed`；两者不得混为普通成功空数组。
- **FR-035**: 只有状态有效、权限合格、版本兼容、达到最低相关性且通过去重/冲突规则的结果才可进入 Coach 的受控上下文。
- **FR-036**: 每次传给模型的 RAG 上下文 MUST 具有批准的最大 Token 预算；超出预算时按排名、证据多样性和回答需要裁剪，并记录被选用与被舍弃的结果数量。
- **FR-037**: 上下文 MUST 把检索材料标记为不可信数据而非指令，并清楚分隔来源元数据、摘录和用户问题；检索文本不能覆盖系统 Prompt、身份、工具权限或工作流规则。
- **FR-038**: 模型可获得结果排名、标准化相关性和引用标识以判断证据强弱；前端第一阶段不展示原始相关性分数，只展示用户可理解的来源与失效状态；完整分数、门槛和排名必须进入脱敏 Trace。
- **FR-039**: 系统 MUST 为后续关键词检索、混合检索或 Reranker 保留不改变业务合同的扩展边界，但第一阶段不得在没有评测证据时强制引入多阶段检索。
- **FR-040**: 检索缓存如存在，MUST 绑定访问范围、认证主体的不可逆标识、过滤器、内容版本、Embedding 版本和检索配置版本；私有结果不得跨用户命中。

#### Structured Retrieval Contract

- **FR-041**: `search_learning_materials` MUST 返回经过版本化 Schema 校验的结构化结果，至少包含：

```text
query: string
appliedFilters: object
results: RetrievalResult[]
citations: Citation[]
retrievalStatus: "success" | "insufficient" | "failed"
```

- **FR-042**: `appliedFilters` MUST 反映服务端最终实际应用的等级、课程、单词、分类、来源、Top K、最低相关性、内容/Embedding/索引版本和访问范围；不得返回原始 `userId`，但必须表明私有范围已由服务端强制执行。
- **FR-043**: 每个 `RetrievalResult` MUST 至少包含 `resultId`、`chunkId`、`documentId`、`citationId`、`source`、`sourceId`、`title`、`category`、`excerpt`、`level`、`courseId`、`wordId`、`rank`、标准化 `relevanceScore`、`contentVersion`、`embeddingVersion` 和结果有效状态。
- **FR-044**: `RetrievalResult.rank` MUST 是本次最终有效结果中的唯一正整数顺序；标准化相关性 MUST 在声明范围内、方向一致且可跨同一检索配置比较，不能把不兼容算法的原始值冒充统一分数。
- **FR-045**: 结果摘录 MUST 来自该结果对应的当前有效 Chunk，处于批准长度内，并经过权限和敏感内容校验；模型或前端不得收到超出任务需要的完整私有文档。
- **FR-046**: `retrievalStatus=success` 时 MUST 至少存在一个合格结果且每个引用均可追溯到其中一个结果；`insufficient` MUST 表示检索完成但没有足够可靠依据；`failed` MUST 表示检索未能可靠完成并带稳定、安全、可重试分类。
- **FR-047**: 无效、低相关性、无权限、失效、版本不兼容或冲突未解决的结果不得出现在传给 Coach 模型的 `results` 中；诊断信息只能进入受控 Trace，不能伪装为回答证据。
- **FR-048**: 工具名称、只读权限边界和服务端认证上下文 MUST 保持与现有 Coach 兼容；合同升级必须版本化，并保证迁移期间任何消费者只接收其声明支持的版本。

#### Citations and Coach Integration

- **FR-049**: 每个 `Citation` MUST 至少包含以下字段，并可保留现有 Coach 的材料类型、定位信息、支持范围和访问范围字段：

```text
citationId: string
source: string
sourceId: string
title: string
excerpt: string
category: string
wordId: string | null
courseId: string | null
```

- **FR-050**: `citationId` MUST 由本次服务端有效检索结果产生，唯一关联一个可验证的 Chunk 与内容版本；模型、Prompt、前端和用户输入不得创建、替换或复活 `citationId`。
- **FR-051**: 最终 Coach 结果 MUST 保留来源级 `citations` 集合，并为回答中的事实性文本块建立显式的声明到 `citationId[]` 关联；学习建议、语气调整或模型生成练习提示必须与知识库事实区分。
- **FR-052**: 每个事实性声明使用的引用 MUST 直接支持该声明；没有来源支持的事实不得带引用，模型常识或生成例句不得被标记为知识库原文。
- **FR-053**: 同一来源或同一 Chunk 被多次使用时，引用集合 MUST 去重，但每个事实性声明仍需保留其引用关联；独立且真实的多来源支持不得被错误合并掉。
- **FR-054**: 最终结果校验 MUST 拒绝任何不属于本次合格检索结果、版本不匹配、当前用户无权访问或摘录不一致的引用；一次受控修复后仍无效时返回合法降级结果。
- **FR-055**: 检索 `insufficient` 时，Coach MUST 明确区分“知识库没有足够依据”和“可以提供非事实性的通用学习建议”；不得为了保持回答完整而生成虚假事实或引用。
- **FR-056**: 检索 `failed` 时，不依赖知识库的 Coach 基础能力、会话状态、取消、重试和已有学习记录 MUST 保持可用；任何需要事实依据的练习或批改不得使用失败检索结果继续生成。
- **FR-057**: Coach MUST 根据用户问题、已验证 CEFR、当前课程、学习目标、薄弱项和到期复习事实构造检索请求；这些信号缺失、过期或不适用时必须保留状态，不能由模型推测。
- **FR-058**: Vue 前端 MUST 以引用卡片展示来源、标题、分类、安全摘录、关联内容和有效状态；单词、课程、语法以及本人私有学习内容只可打开当前用户有权访问的详情。
- **FR-059**: 历史回答中的引用在原始内容删除、版本失效或权限变化后 MUST 显示失效/不可访问状态，且不得继续返回受限摘录；系统不得把旧引用自动绑定到语义相似但不同的新来源。

#### Identity, Security, Privacy, and Retention

- **FR-060**: 所有检索身份 MUST 只来源于经验证的服务端 JWT access-token 上下文；前端参数、Prompt、会话历史、模型输出、过滤器或工具参数中的 `userId` 必须被忽略或拒绝。
- **FR-061**: 公共知识仅可在其来源授权范围内供合法用户检索；私有 Chunk 只能由其服务端所有者检索；课程内容还必须满足最终确认的课程访问策略。
- **FR-062**: 私有访问过滤 MUST 由服务端在每次向量查询、补充查询、缓存读取、引用解析和历史引用打开时强制添加，不能只依赖模型、Prompt 或调用方提供过滤器。
- **FR-063**: 用户不能通过自然语言、嵌入文本、过滤条件、课程/单词标识、`citationId`、分页、Top K、最低相关性或工具重试推断或读取其他用户的私有内容。
- **FR-064**: 写入知识库的公共与私有内容 MUST 经过来源、结构、长度、内容状态、访问范围、恶意指令和敏感数据校验；失败数据不得生成有效向量。
- **FR-065**: 知识文本中的指令性内容 MUST 始终被当作数据；它不得修改系统 Prompt、工具白名单、身份、检索过滤、模型预算、输出 Schema 或写操作权限。
- **FR-066**: Embedding Provider 只能接收生成向量所需的最小正文；不得接收 JWT、API Key、联系方式、支付信息、原始 `userId`、无关会话或不必要的来源元数据。
- **FR-067**: 私有 Chunk、向量和引用摘录不得进入其他用户的 Prompt、缓存、Trace 内容、人工审阅队列或评测样本；默认 RAG 评测使用合成或专门授权数据。
- **FR-068**: 日志和 Trace MUST NOT 记录 JWT、刷新令牌、API Key、数据库凭证、原始系统 Prompt、内部推理、完整私有文档或不必要的用户学习原文；用户主体继续使用不可直接反查的标识。
- **FR-069**: 用户删除错题、学习摘要、Coach 数据或账户时，对应私有文档、Chunk、向量、缓存和引用详情 MUST 立即隐藏，并在现有 Coach 隐私门槛要求的 24 小时内从主存储物理清除。
- **FR-070**: 公共或课程知识在来源删除、到期、撤权或内容更新时 MUST 立即停止检索；失效副本只可按经批准的审计/回滚政策受控保留，且不得包含已撤销授权不允许继续保存的内容。
- **FR-071**: RAG Trace 元数据 MUST 与现有 Coach Trace 对齐保留 180 天；含脱敏问题或摘录的诊断内容默认关闭，显式启用时最多保留 7 天；到期后必须删除。
- **FR-072**: RAG 评测的合成与人工编写样本可按版本保留以复现回归；任何专门授权的私有样本必须记录授权和删除条件，并在授权撤销或用户删除后 24 小时内移除所有副本和派生向量。
- **FR-073**: 原始知识内容的保留不得超过其权威业务记录和来源授权期限；Embedding 与 Chunk 不得在原始内容失效后继续作为有效数据，物理保留上限必须在生产启用前形成可审计政策。

#### Observability and Evaluation

- **FR-074**: 每次 RAG 请求 MUST 关联现有 Coach Trace ID，并记录脱敏问题或摘要、实际过滤器、Top K、最低相关性、Embedding 模型及版本、Chunk/内容/索引版本、结果数量、排名、来源、相关性、冲突/去重决策、检索耗时、上下文 Token、实际使用引用、空召回/降级/异常和用户反馈。
- **FR-075**: Trace MUST 能区分原始召回数量、权限过滤后数量、相关性过滤后数量、去重后数量和最终进入模型上下文的数量，但不得暴露其他用户结果的内容或可反推标识。
- **FR-076**: 每次最终回答 MUST 能从 Trace 追溯到本次检索、最终上下文、声明引用关联和用户反馈；未被最终回答使用的结果必须与已使用引用可区分。
- **FR-077**: 现有 Coach 评测集 MUST 增加版本化 RAG 专项样本，至少覆盖单词释义、词性/音标/词形、例句/搭配、语法、课程、等级过滤、个人错题/摘要、空召回、低相关性、相似错误知识、来源冲突、Prompt Injection、跨用户攻击、虚假引用、内容更新/删除/重新向量化、延迟、上下文 Token 和总 Token/成本。
- **FR-078**: 每条评测样本 MUST 关联样本版本、用户等级、课程/单词/分类过滤、公共或私有访问范围、允许来源、预期相关 Chunk、禁止来源、内容/Embedding/检索配置版本和判定方式。
- **FR-079**: 评测 MUST 计算以下指标，且定义保持版本化：

| Metric | Definition | Judging mode |
|--------|------------|--------------|
| Recall@K | Top K 合格结果中命中的标注相关 Chunk 数 ÷ 该样本全部标注相关 Chunk 数。无相关 Chunk 的空召回样本单独统计，不纳入该分母。 | 自动化集合比对，标注集由人工/授权数据准备 |
| Precision@K | Top K 合格结果中标注相关 Chunk 数 ÷ 实际返回的合格结果数。空结果按场景期望单独判定。 | 自动化集合比对 |
| MRR | 每个存在相关答案的样本中首个标注相关结果排名倒数的平均值。 | 自动化排名计算 |
| Citation accuracy | 来源、内容版本、摘录和声明支持关系均正确的引用数 ÷ 全部引用数。 | 标识/版本自动校验 + 内容支持人工或独立模型评分 |
| Citation coverage | 具有至少一个有效支持引用的应引用事实性声明数 ÷ 全部应引用事实性声明数。 | 声明抽取规则 + 人工或独立模型复核 |
| Answer faithfulness | 能由本次最终上下文直接支持的事实性声明数 ÷ 最终回答全部事实性声明数。 | 人工或独立模型按固定量表评分，抽样复核 |
| Unsourced claim rate | 需要知识来源但没有有效支持引用的事实性声明数 ÷ 全部应引用事实性声明数。 | 规则检测 + 人工或独立模型复核 |
| Schema pass rate | 首次或受控修复后通过声明合同的检索和最终结果数 ÷ 全部结果数；同时单独报告首次通过率。 | 自动化 Schema 校验 |
| Cross-user leakage rate | 跨用户攻击样本中出现任何非当前用户私有结果、摘录、引用、Prompt、缓存或 Trace 内容的样本数 ÷ 攻击样本数。 | 自动化金丝雀与权限断言；任何非零均失败 |
| Prompt Injection pass rate | 恶意知识文档未改变指令、权限、工具或输出边界的样本数 ÷ 注入样本数。 | 自动化行为断言 + 输出扫描 |
| Retrieval latency | 从已验证检索请求开始到结构化检索结果就绪的耗时，按 P50、P95 和最大值报告。 | 自动化计时 |
| Context tokens | 本次实际传给 Coach 模型的 RAG 上下文 Token，按 P50、P95 和最大值报告。 | 与生产一致的 Token 计数 |
| Total tokens and cost | RAG 请求引发的 Embedding、检索后模型调用及受控重试的总 Token 与按版本价格计算的总成本。 | 自动化用量与价格版本计算 |

- **FR-080**: 相关性标注、引用支持、忠实度和冲突判断所用人工或独立模型量表 MUST 在运行前固定；评分者不得看到不必要的真实身份数据，争议样本必须可复核。
- **FR-081**: 认证、跨用户隔离、Prompt Injection、任意 `userId` 注入、虚假 `citationId`、无来源引用、失效来源继续返回和 Schema 绕过 MUST 是零容忍阻断项，不能被平均检索质量抵消。
- **FR-082**: 尚无可信基线的 Recall@K、Precision@K、MRR、引用覆盖率、忠实度、延迟、Token 和成本 MUST 先在固定数据集与环境测量；目标和允许回退范围只有在记录并批准基线后才能生效，不得凭空声称达标。
- **FR-083**: Prompt、Embedding 模型、Chunk 策略、检索参数、最低相关性、Top K、访问过滤或结果 Schema 变化后 MUST 运行完整 RAG 回归集；只变更单一组件也不能跳过安全、引用和跨用户样本。
- **FR-084**: RAG 发布报告 MUST 同时列出数据集、来源授权快照、Prompt、Embedding、Chunk、索引、检索配置、Schema、价格版本和实际指标；缺失版本或未批准基线时保持发布门禁关闭。

### Key Entities *(include if feature involves data)*

- **Knowledge Source**: 一项知识内容的来源与权利台账；包含来源名称、来源类型、授权状态、允许用途、有效期、核验状态和版本，不把品牌字段名当作许可证。
- **Knowledge Document**: 从一个真实业务对象规范化出的可检索文档；关联 Knowledge Source、原始业务记录、内容版本、访问策略、处理状态和生命周期。
- **Knowledge Chunk**: Knowledge Document 中可独立表达学习含义的片段；包含正文、必需元数据、Chunk 策略版本、有效状态，并可关联多个真实业务分类但只有一个明确访问策略。
- **Embedding**: 某个 Chunk 在特定 Embedding 版本下的向量表示；只有维度、版本、状态和父 Chunk 均兼容有效时可参与检索。
- **Content Release**: 一组同时生效且彼此兼容的内容、Chunk、Embedding 和检索配置版本；防止更新或重处理期间混用无效版本。
- **Retrieval Request**: 某次 `search_learning_materials` 调用的结构化请求；包含问题、业务过滤、服务端强制访问范围、Top K、相关性门槛、预算和版本。
- **Retrieval Result**: 本次请求中通过访问、有效性、相关性、去重和冲突规则的 Chunk 结果；包含排名、标准化相关性、版本和对应引用标识。
- **Citation**: 对本次有效 Retrieval Result 的用户可展示证据；包含不可伪造的 `citationId`、来源、标题、摘录、分类和业务定位。
- **Claim-Citation Link**: 最终回答中一个事实性声明与一个或多个 `citationId` 的显式关系，用于校验、卡片定位和引用覆盖率评测。
- **Private Learning Summary**: 当前用户从已保存错题、练习和学习历史中产生的最小化结构化摘要；不等同于完整会话，随原始记录删除或失效。
- **RAG Trace Segment**: 现有 Coach Trace 内的检索观测记录；串联请求、过滤、版本、召回、上下文、引用、回答、反馈、延迟、Token 和成本，同时遵守脱敏规则。
- **RAG Evaluation Case/Run**: 可重复的检索与回答评测输入、金标准、访问边界、版本和结果，用于比较质量并执行发布门禁。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 发布到可检索集合的知识文档具有可审计来源、内容版本和有效授权状态；未确认授权的第三方词典、课程或例句内容进入有效集合的数量为 0。
- **SC-002**: 对同一来源、内容版本、Chunk 策略和 Embedding 版本重复摄取任意次数后，有效文档、Chunk 和向量数量不增加，重复有效 Chunk 数为 0。
- **SC-003**: 在更新、删除、撤权和重新向量化验收中，旧版本或失效内容出现在新检索结果中的数量为 0；历史引用均能正确显示有效或失效状态。
- **SC-004**: 单词、课程、语法、练习知识、本人错题和本人学习摘要的所有具备授权且有样本的类别均可被独立检索；尚无真实语料的类别明确返回不可用或依据不足，不伪造命中。
- **SC-005**: 100% 等级、课程、单词、分类、来源、Top K 和最低相关性过滤测试返回的结果符合服务端最终过滤器，越权或无效过滤器扩大结果范围的次数为 0。
- **SC-006**: 100% 传给 Coach 的检索结果通过权限、状态、版本、相关性、去重和冲突门禁；不合格结果进入最终 Prompt 的数量为 0。
- **SC-007**: 100% 最终 `citationId` 来自同一次真实有效检索结果并支持其关联声明；伪造、过期、越权或摘录不一致的引用到达用户的数量为 0。
- **SC-008**: 在空召回、低相关性、冲突未解决和检索异常样本中，100% 返回正确的 `insufficient` 或 `failed` 状态，并产生不含虚假引用的合法 Coach 降级结果。
- **SC-009**: 跨用户攻击评测的私有数据泄露率为 0；用户 A 的私有 Chunk、摘录、引用、Prompt、缓存和 Trace 内容出现在用户 B 请求中的数量为 0。
- **SC-010**: Prompt Injection 防护样本通过率为 100%；知识文档改变系统指令、认证主体、访问过滤、工具权限或输出合同的次数为 0。
- **SC-011**: 100% 检索响应和最终 Coach 响应通过其声明的版本化结构合同；模型生成但本次不存在的 `citationId` 通过最终校验的数量为 0。
- **SC-012**: 100% RAG 请求可通过一个 Trace 关联实际过滤、版本、召回排名与相关性、检索耗时、上下文 Token、实际引用、最终回答和反馈；敏感信息扫描发现的禁止内容为 0。
- **SC-013**: 100% 发送给模型的 RAG 上下文不超过批准的最大 Token 预算；超预算样本均按声明规则裁剪并在 Trace 中记录。
- **SC-014**: Vue 前端对每个有效引用显示去重卡片和关联来源；在权限允许时，测试用户可在一次点击内打开对应单词、课程、语法或本人私有学习详情；失效引用不会展示受限原文。
- **SC-015**: RAG 专项评测集覆盖 FR-077 的全部类别，并为 Recall@K、Precision@K、MRR、引用正确率、引用覆盖率、忠实度、无来源内容占比、Schema、泄露、注入、P50/P95 延迟、上下文 Token 和总 Token/成本生成可重复报告。
- **SC-016**: 首个候选版本在固定数据集和环境中完成当前版本测量并获得明确批准后才可设定质量、延迟和成本目标；后续候选不得超出批准回退范围，严重安全或虚假引用失败始终阻止发布。
- **SC-017**: RAG 检索失败、超时或禁用时，现有 Coach 的认证、会话、流式状态、取消、重试及与知识库无关的基础问答仍返回其声明的合法状态，故障导致的学习数据错误写入数量为 0。
- **SC-018**: 现有 Coach 确定性与浏览器回归集以及登录、刷新、词典、课程、10 词学习、批量掌握、普通 AI 和非 AI 页面验收无新增阻断性缺陷或未经批准的行为变化。

## Out of Scope

- AI 发音评测、语音打分和音频向量检索。
- English Learning MCP Server。
- 多 Agent 系统或独立 RAG Agent。
- 对互联网进行无边界自动抓取或把普通联网搜索当作本知识库来源。
- 未经授权的 Oxford、Collins 或其他词典、课程、例句内容采集。
- 完整知识管理后台、复杂人工审核和大规模内容运营工作流。
- 自动修改、覆盖或纠正权威课程和词典原始数据。
- 将全部历史会话原文直接写入向量库。
- 与 RAG 无关的 Coach 工作流重构、支付变更或非 AI 功能改造。
- 独立大规模向量数据库集群。
- 在没有评测证据前引入强制关键词融合、复杂多阶段检索或 Reranker。
- 本 Specify 阶段的技术方案、代码、任务拆分、依赖安装、数据库迁移、索引创建、部署、提交或推送。

## Clarify-Stage Questions

1. **Dictionary rights and provenance**: `WordBook.definition`、`translation`、`phonetic`、`pos`、`exchange`、BNC/FRQ 以及 `collins`/`oxford` 字段分别来自哪里、采用什么许可证、允许哪些展示/Embedding/衍生评测用途？在答案确认前，这些字段只能按逐来源白名单进入知识库。
2. **Course access classification**: 课程正文与课程元数据应继续仅限已购用户，还是存在可供所有已登录用户检索的公共子集？最终答案需要同时确定共享 Chunk 的访问策略、引用打开行为和缓存隔离边界。
3. **Public stale-copy retention**: 公共/课程内容失效后的非检索副本是否需要短期审计或回滚保留，以及授权撤销时是否要求立即物理删除？无论答案如何，失效内容都必须立即退出检索和引用详情。

## Assumptions

- 目标用户仍是当前 Web 应用中的已登录学习者，不新增教师、管理员代查或组织多租户角色。
- 现有 JWT access-token 与 `CoachExecutionContext.subjectId` 继续作为唯一用户身份来源。
- `search_learning_materials` 保持只读工具；本功能不会新增由模型触发的知识库管理或业务写工具。
- 课程访问在 Clarify 完成前沿用现有“已购课程才可访问”的更严格边界，任何方案不得临时放宽权限。
- 词形信息可来自当前 `exchange` 字段，但只有在来源含义和授权确认后才作为可引用事实使用；字段注释“同义词”与用户期望的“词形变化”之间差异属于数据质量核验项。
- 例句、搭配、语法和课程正文若没有合法真实数据，第一阶段允许对应类别保持不可用，不允许用模型生成内容冒充语料。
- 用户私有历史只摄取最小化结构化摘要和已验证错题事实，继续遵循现有 Coach 的删除与隔离门槛。
- 原始相似度可能因检索配置不同而不可比，因此面向合同使用声明范围内的标准化相关性；具体算法、索引和归一化方式留到 Plan 阶段。
- 关键词检索、混合检索和 Reranker 仅保留兼容边界，是否启用必须由基线和专项评测证据支持。
- 项目宪章当前仍是未填写模板，不提供额外治理约束；若后续宪章生效并与本规格冲突，应先更新本规格。

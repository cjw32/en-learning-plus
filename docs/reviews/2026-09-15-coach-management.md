# Coach 历史与管理入口验收（2026-09-15）

已补齐原项目审查中 Coach 历史、反馈与删除的页面缺口。对应 `specs/001-personalized-learning-coach/tasks.md` CM-01–CM-05。未更换模型或改变学习算法。

## 用户入口与行为

顶部导航「Coach」→ `/en/coach/index`。左侧「历史会话」支持自定义新会话名称、会话切换、分页加载、刷新、单会话删除；正文支持消息分页，每条有关联请求的 Coach 回答下方可提交或修改反馈，支持原因和说明。反馈重试沿用相同幂等键，刷新历史后读取保存结果。左侧「Coach 数据管理」提供全部 Coach 数据删除，并明确其覆盖会话、反馈、学习画像、作答和复习数据。两种删除均需用户确认。

会话读取/删除中禁止发送，回答进行中需先完成或取消后再管理。切换会话清空临时流、重试、练习提交状态；已离开会话或旧账号的迟到响应不回写。删除失败保留当前内容并支持重试，受理后立即清空相关页面内容。单会话删除不宣称撤销此前已保存的学习记录。

## 接口与数据库

历史 API 增补真实 requestId 和当前用户未过期反馈的公开投影。查询沿用用户归属校验，不返回内部请求、模型输入或认证信息；不从 traceId 推算反馈请求。

实际联调发现旧迁移将 `CoachTrace.traceSubjectId` 设为非空，和现有 Prisma nullable 定义及删除关联的契约不一致。新增兼容迁移 `20260915000000_coach_trace_nullable_subject`，只移除非空约束；已在项目独立本机数据库执行。其他环境更新此版本时也须执行迁移。

本机 Docker 数据服务因未运行导致第一次真实联调失败，现已恢复原有 PostgreSQL、Redis、MinIO 容器并保留数据卷，重新启动 AI 服务。`server/.env` 的 `COACH_ENABLED=true` 已打开基础管理接口，`COACH_LIVE_MODEL_ENABLED` 和 `COACH_WRITE_ENABLED` 仍关闭。本次完成的是历史与管理功能，不代表 Coach 真实模型生成已开启。
